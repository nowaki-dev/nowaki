# Nowaki v0.2 「Breeze」 — 実装計画

> [ROADMAP.md](../ROADMAP.md) の v0.2 を、コードベースに即した具体タスクへ分解したもの。
> テーマ: **DX & 正しさ**。Exit基準: 小規模な実アプリを快適にドッグフーディングできる。

## 進め方（推奨シーケンス）

価値と安全性で前詰めする:

- **Phase A — 即効の小物**（低リスク、すぐ効く）
- **Phase B — DX の核**（エラーオーバーレイ, 環境変数）
- **Phase C — 実アプリ要件**（CSS, SSG コマンド）
- **Phase D — 大物**（状態保持 HMR / prefresh）

各タスクは「どこを触るか」「完了条件」「規模(XS〜L)/リスク」で定義する。すべて
`cargo fmt`/`clippy` クリーン維持 + example アプリで実際に動かして検証（ドッグフード）。

## Phase A — 即効の小物

### A1. `nowaki --version`
- **どこ**: `crates/nowaki/src/main.rs` の `Cli` に `#[command(version)]`（clap が `CARGO_PKG_VERSION` を読む）。
- **完了**: `nowaki --version` が `nowaki 0.1.x` を表示。
- 規模 XS / リスク なし。（ドッグフーディングで発覚済みの抜け）

### A2. build 仕上げ — modulepreload + island無しページの runtime 省略
- **modulepreload**: `build_client` は emit 時に依存グラフを持つ。manifest に各 island の依存チェーン（or 全アセット）を追加し、`render.mjs`/`start.mjs` が runtime + 使用 island の `<link rel="modulepreload">` を `<head>` に注入（瀑布リクエスト回避）。
- **runtime 省略**: 現状 `render.mjs`/`start.mjs` は常に islands.js を読み込む。vnode フックが島を描画したかをリクエスト毎にフラグ化し、**島が1つも無ければ runtime `<script>` を出さない**（about 等は完全 JS ゼロに）。
- **完了**: 島無しページは runtime script を含まない。島ありページは island チャンクを preload。
- 規模 S-M / リスク 低。

### A3. 診断の改善（コードフレーム）
- **どこ**: `crates/nowaki-core/src/transform.rs`。今は oxc 診断を文字列連結。oxc 診断は span を持つので、`file:line:col` + 該当行 + キャレット付きのコードフレームで表示（miette か oxc の diagnostic renderer）。
- **完了**: 構文エラーがファイル・行・位置のキャレット付きで出る。
- 規模 M / リスク 低。（B1 の前提にもなる）

---

## Phase B — DX の核

### B1. エラーオーバーレイ（dev 専用） ★flagship
- **狙い**: 変換エラー(Rust)・SSRエラー(Node)・ランタイムエラーを、コンソールや素の500でなくブラウザに全画面オーバーレイで表示。次の成功ビルドで自動消去。
- **構成**:
  1. クライアントのオーバーレイモジュール（`@nowaki-dev/runtime/client`）が HMR WS の `{type:"error", message, frame, stack}` を受けて描画。
  2. Rust dev サーバーが変換失敗時に HMR WS へ `error` を送る（`crates/nowaki/src/dev.rs` の watcher/transform に hook 点あり。A3 のコードフレームを同梱）。
  3. SSR サイドカーが描画失敗時、オーバーレイ入りの HTML を返す（`render.mjs` の catch）。
- **完了**: ファイルを構文エラーにするとオーバーレイ表示、直すと消える。
- 規模 M / リスク 中（UX + 配線）。

### B2. 環境変数
- **狙い**: `.env`(+`.env.local`) を dev/build 開始時に読み込む。サーバー側は `process.env`。クライアント側は **`PUBLIC_` 接頭辞のみ露出**し、変換時に `import.meta.env.PUBLIC_X` をリテラルへインライン化（browser モード）→ 秘密は配信されない。
- **構成**: Rust で dotenv 読込（or サイドカーへ環境を渡す）+ oxc 変換パスで `import.meta.env.PUBLIC_*` / `import.meta.env.MODE` を browser モードで定数置換。
- **完了**: `PUBLIC_FOO` が island で使え、クライアントバンドルにインライン化。非PUBLICは露出しない。
- 規模 M / リスク 中（変換時置換）。

## Phase C — 実アプリ要件

### C1. CSS 対応（まずグローバル import）
- **狙い**: `import "./app.css"` をサポート。
  - dev: 副作用 import を、`<link>`/`<style>` を注入する JS シムに書き換え（or CSS を配信して `<link>` 注入）。
  - build: CSS を収集して `dist/client` へ出力し、ページに `<link>` を追加（manifest 経由）。
- **後続**: CSS Modules / scoped styles（より大きい）。まずグローバル CSS から。
- **完了**: route/island が `import "./styles.css"` で dev/prod とも適用される。
- 規模 M-L / リスク 中。（ランディングが inline + Tailwind CDN で凌いだ部分の本対応）

### C2. `nowaki prerender`（SSG）— ランディングの手動フローを正式化
- **狙い**: 静的ルート（動的paramや非決定的loaderが無いもの）を各々 HTML 化し静的ディレクトリへ出力（`site/scripts/prerender.sh` が手動でやっていること）。
- **構成**: ルート列挙 → サイドカーで各描画 → HTML 書き出し + `dist/client`→`static/_nowaki` コピー。`[slug]` は `getStaticPaths` export で（後続）。
- **完了**: `nowaki prerender <dir>` がデプロイ可能な静的ディレクトリを生成（prerender.sh を置換）。
- 規模 M / リスク 低（アプローチ実証済み）。

## Phase D — 大物

### D1. 状態保持 HMR（prefresh）
- **狙い**: 現状の full live-reload を、**島の state を保持したモジュール単位ホットスワップ**に置換。
- **構成**:
  1. `kaze-core` に逆辺付きモジュール依存グラフ（変換時に import を記録）。
  2. HMR プロトコル `{type:"update", module, ...}`。
  3. クライアントに prefresh ランタイム（Preact Fast Refresh）+ 変換が refresh 登録を注入（oxc の react-refresh 変換があれば利用、無ければ自前パス）。
  4. クライアントが変更 island モジュールを再 import し、state 保持のまま再マウント。
- **完了**: island の render を編集しても `useState` が保持される（full reload 無し）。
- 規模 L（v0.2 最大）/ リスク 高。
- **中間案**: まず full-page reload を避けた「該当モジュールのみ再評価（state はリセット）」を出して、prefresh は次段でも可。

## 横断
- **テスト**: 変換のスナップショットテスト + 新機能の e2e を少しずつ。
- **循環依存**: build の循環エラー（Phase 1 制約）を、後順DFSの cycle 検出で「pre-rewrite ハッシュ」フォールバックする対応も C/D 期に。
- **公開 runtime**: head 注入・lang・(B/C の) 変更が固まったら `@nowaki-dev/runtime` を 0.1.x で再 publish（現状ローカルworkspaceのみ）。
